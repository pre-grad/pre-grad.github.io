Workload rules
While unemployed, plan roughly 29 focused hours and keep the remaining weekly time uncommitted for delays and interviews. After full-time employment, switch immediately to the roughly 10-hour schedule.
Only the next 14 days become ready. Later tasks stay weekly, and unselected branches create no tasks. Previous course percentages or AI-assisted output do not prove completion.
For a strict no-AI task, attempt and score the work independently. AI may critique the result only after the attempt; generated implementation cannot substitute for the pass check.
Explicitly skipped or postponed
Do not continue Functional Programming beyond on-demand concepts or build the Boot.dev AI Agent.
Do not start RAG, Static Site Generator, Memory Management, JavaScript, TypeScript, Go or language-specific backend courses before Project 1 unless repeated job evidence changes the lane.
No Kubernetes before employment; no payments, large frontend, multiple providers, microservices or live customer credentials in Projects 0–1.
Do not pay for AWS Cloud Practitioner, Azure Fundamentals, PCEP, generic Java, GitHub Foundations, Kubernetes, Security+ or random MOOC certificates. PCAP remains dormant until Project 1 and repeated employer demand.
Do not take both AWS and Azure associate certifications. Do not add Kafka or a second orchestrator before Project 2 batch processing works.
Power BI, Pandas, Terraform, Databricks, security and ML enter only when real project or repeated interview evidence justifies them.

Decision Branches

First-week builds decide what to repair
The first Python, SQL, Linux/Git and DSA tasks name the exact files, commands and problems to complete. A failed part creates one targeted repair and retry; it never creates an unrelated new course.
Certification is conditional
AWS learning begins through the real Project 1 after its thin MVP. DVA-C02 remains the default paid technical credential and starts only if practical, admissions and interview conditions are met. GitHub Actions, PCAT, LFCS, EDB, dbt and Airflow credentials remain dormant until their named project, experience and employer-signal gates pass. Evidence-based deferral is a correct outcome.
Programme applications are conditional
The August gate resolves prerequisites, English, referees, mathematics evidence and the funding ceiling. UBC, SFU, McMaster, Concordia and Dalhousie create their own task sequence only after that milestone passes and the live 2027 cycle has been reverified.
May lane probe
If still unemployed, choose exactly one two-week probe from Java/Spring Boot, QA automation/Playwright, Power BI, security hardening or ML systems—only when application/interview evidence supports it. Stop the probe if it produces no signal.
15 June 2027 route decision
Compare employment quality with verified programme fit, cost, work integration, funding, PGWP, delivery mode and deferral. Select one route deliberately. Do not plan a mid-programme departure from a strong overlapping graduate programme.
No new giant project or second certification is allowed to postpone a decision the evidence can already make.

Settings

Backup, restore & delete
Everything (settings, tasks, applications, weekly and monthly reviews, evidence, branch state, capacity, and completion history) lives in localStorage under hamza-master-execution-v2. This section gives you a real full-state backup and restore path for GitHub Pages: export JSON, import that JSON later, or deliberately wipe this browser's saved copy.
🧯
Do not rely on browser storage alone. Export every Sunday after weekly review. Restoring replaces the entire planner state with the imported JSON. Delete/reset actions are irreversible unless you exported first.
Deploy on GitHub Pages
1.
Save this file as index.html in a new repo (e.g. hamza-execution-planner).
2.
Push to GitHub. Settings → Pages → deploy from main / root.
3.
Live at https://<you>.github.io/hamza-execution-planner/.
4.
Bookmark on phone & desktop. Each device's data is independent — use Export/Import to sync.
