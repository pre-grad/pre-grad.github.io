Workload rules
Start at roughly 22 focused hours per week. Earn any increase through four weeks of finished work, not optimism. After full-time employment, switch immediately to a reduced role-first schedule.
Only the next 14 days become ready. Later tasks stay weekly, and unselected branches create no tasks. Previous course percentages or AI-assisted output do not prove completion.
For a strict no-AI task, attempt and score the work independently. AI may critique the result only after the attempt; generated implementation cannot substitute for the pass check.
Explicitly skipped or postponed
Do not continue unrelated Boot.dev courses merely because they exist. Finish only Linux, SQL, DSA/DSA2, HTTP Clients, Docker, AWS and Job Search as mapped to active outcomes; use the uploaded roadmap.sh maps only to close selected Python-project, networking, API-design, QA, secure-engineering and activated data-service gaps.
Do not start Functional Programming, AI Agent, Static Site Generator, Memory Management, JavaScript, TypeScript, Go, RAG or another backend language before the job-ready release unless a real assessment or employer requirement changes the plan.
Project One remains a bounded career-pipeline API. No payments, multi-tenancy, billing, microservices, Kubernetes, multiple providers or large frontend are required for the umbrella goal.
Pandas and machine learning begin only through the selected April–May overlay. The data branch is a connected data-contract, idempotent-ingestion and SQL-first analytics extension; an interpretable model and MLOps-lite evidence appear only when their trigger is real. Airflow, Spark, Kafka, warehouses, Kubernetes, feature stores and registry platforms stay deferred.
Cloud Practitioner is the first possible cloud credential; Developer Associate is second only after deeper real work and market value; ISC2 CC exists only for a rising cyber branch. Evidence-based deferral is a correct result.
Formal transcript-bearing maths/statistics remediation outranks vendor badges whenever a retained programme confirms a credit prerequisite.

Decision Branches

The umbrella core stays active
Python, Linux, Git/GitHub, SQL/PostgreSQL, DSA, practical networking, HTTP/API design, FastAPI, pytest/QA work, secure defaults, Docker, CI and AWS are the shared spine. Failed exits create targeted repair work; they do not create a new career direction.
Exactly one light overlay
After the cloud-ready release and two job-funnel reviews, activate one bounded cyber, data/ML, deeper software/cloud or employed-maintenance branch. The data/ML option additionally requires confirmed maths/prerequisite requirements, an obtainable dataset and a five-week release contract. All other overlays remain absent.
Certifications come after hands-on work
Certificates are optional. Cloud Practitioner is the quick AWS signal after the labs; Developer Associate comes only after the live project has been operated; LFCS is useful only if Linux-heavy roles become a real target; ISC2 CC belongs only to a completed cyber overlay.
Programme applications are conditional
BCIT Applied Computing, UBC MEng ECE, SFU Cybersecurity, SFU Visual Computing, SFU Big Data and UBC MDS create application tasks only after live eligibility, prerequisite, affordability and cycle checks pass. UBC MEL remains watchlist-only while paused or experience-ineligible.
15 June 2027 route decision
Compare real UAE employment results with admissions, programme fit, total cost, funding, current immigration facts and start dates. Activate exactly one employment, study-transition or continued-search route.
No new giant project or second certification may postpone a decision that the real options already make clear.

Settings

Backup, restore & delete
Everything (settings, tasks, applications, optional notes, branch state, and completion history) lives in localStorage under hamza-master-execution-v2. This section gives you a real full-state backup and restore path for GitHub Pages: export JSON, import that JSON later, or deliberately wipe this browser's saved copy.
🧯
Do not rely on browser storage alone. Export occasionally after major progress or before resetting. Restoring replaces the entire planner state with the imported JSON. Delete/reset actions are irreversible unless you exported first.
Deploy on GitHub Pages
1.
Save this file as index.html in a new repo (e.g. hamza-execution-planner).
2.
Push to GitHub. Settings → Pages → deploy from main / root.
3.
Live at https://<you>.github.io/hamza-execution-planner/.
4.
Bookmark on phone & desktop. Each device's data is independent — use Export/Import to sync.
