Workload rules
Start at roughly 22 focused hours per week. Earn any increase through four weeks of finished work, not optimism. After full-time employment, switch immediately to a reduced role-first schedule.
Only the next 14 days become ready. Later tasks stay weekly, and unselected branches create no tasks. Previous course percentages or AI-assisted output do not prove completion.
Do not create standalone “exit” exercises just to prove a completed course. Independence is checked where it matters: building, debugging, changing and explaining the real backend project or handling an actual interview-style task.
Re-angle; do not restart. No new course, certification, language, project, or planner redesign enters the active plan unless a current task, verified employer response, or confirmed programme requirement creates the need.
DSA is mandatory, not a gate in front of backend work. Once SQL/PostgreSQL is usable, HTTP and FastAPI may proceed while DSA continues in parallel. Do not delay employer-visible backend evidence just to finish every algorithm lesson first.
Practice is cross-stack, not DSA-only. Boot.dev Training Grounds stays active across the whole job-relevant stack: one current/weak-skill review, one rotating retention challenge from already-learned Python/Linux/Git/SQL/PostgreSQL/HTTP/API/testing/Docker/CI/AWS skills, and one interview-style challenge matched to the roles currently unlocked. DSA gets a separate specialist lane: once Boot.dev DSA actually starts, add a small LeetCode rep on already-covered topics; after DSA 1, expand to three short Codewars/LeetCode reps per week; after DSA 2, use five short weekday interview-fluency reps. Training Grounds never collapses into a DSA-only tool, and generated drills never replace real PostgreSQL, FastAPI, pytest, Docker, CI, AWS, course completion or Project One deliverables.
The UAE search starts selectively now. In the current graduate-baseline tier, send roughly 2–3 highly qualified applications per week using only evidence you can defend today. Technical learning/building remains the majority of the workload. The Applications page widens role families and raises the target only when SQL/PostgreSQL, HTTP/FastAPI, tested backend work, Docker/CI/public release and AWS evidence actually become true. Week 6 / 31 August is a systematic-search checkpoint, not a permission date.

Decision Branches

The umbrella core stays active
Python, Linux, Git/GitHub, SQL/PostgreSQL, DSA, HTTP/API design, FastAPI, pytest/QA work, secure defaults, Docker, CI and AWS are the shared spine. Linux is already complete; weaknesses discovered in the real project or job process create targeted repair work, not standalone exit exams.
At most one light overlay
After the cloud-ready release and two job-funnel reviews, activate at most one bounded cyber, data/ML, deeper software/cloud or employed-maintenance branch—or choose none. Re-angle the current role search before adding a specialization. The data/ML option additionally requires confirmed maths/prerequisite requirements, an obtainable dataset and a five-week release contract. All other overlays remain absent.
Certifications come after hands-on work
Certificates ratify hands-on work; they do not replace it. AWS Cloud Practitioner is an optional quick signal only after the Boot.dev AWS course and AWS labs. AWS Developer – Associate is the stronger backend/cloud credential and stays locked until Project One is deployed and operated on AWS. LFCS is optional only if Linux-heavy backend/support/cloud roles become a real target. Do not add PostgreSQL, Python, Docker or QA certificates by default.
Programme applications are conditional
BCIT Applied Computing, UBC MEng ECE, SFU Cybersecurity, SFU Visual Computing, SFU Big Data and UBC MDS create application tasks only after live eligibility, prerequisite, affordability and cycle checks pass. UBC MEL remains watchlist-only while paused or experience-ineligible.
Employer funnel: re-angle, do not restart
Use repeated employer signal to change positioning, not one rejection. Backend/Python traction means stay the course. QA automation, application support or cloud/platform traction means re-angle the same umbrella toward that role family. If data-oriented engineering roles clearly outperform after enough real applications, the later data overlay may be considered. If nothing responds, diagnose eligibility, CV top-third, project proof and targeting before buying another course.

This section gives you a real full-state backup and restore path for GitHub Pages: export JSON, import that JSON later, or deliberately wipe this browser's saved copy.
